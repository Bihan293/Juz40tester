# Слабые темы: аудит и новая логика (2026-10-01)

## Что было (фактическая логика до исправления)

Отдельной статистики по темам не было. `WeakTopics` группировал **статусы отдельных вопросов** (`user_question_progress`) по полю `topic`: тема была «слабой», если хоть один отвеченный вопрос темы не 🟢.

Ошибки:
1. 🟡 ставится после *первого правильного* ответа, поэтому тест, пройденный на 20/20, делал **все** темы слабыми.
2. Одна ошибка = слабая тема, систематичность не учитывалась.
3. «🏁 Закончить тест» удалял прогресс по вопросам персонального теста, и результаты практики терялись. Тема переставала быть слабой, только если перепройти *те же самые вопросы*.
4. Кэш по отпечатку тем возвращал пользователю **клон того же теста**, который он уже закончил, то есть те же вопросы.
5. Темы группировались с учётом регистра и пробелов («Клетка» ≠ «клетка»).
6. Перепрохождение теста ради разблокировки накручивало «знание», хотя это было запоминание конкретных вопросов.

Что было в порядке и сохранено: разделение по `subject_id`, хранение в PostgreSQL (переживает перезапуски), транзакция ответа, система 🔴🟡🟢 по вопросам и планка 15🟢+5🟡 для разблокировки тестов.

## Как работает сейчас

- `user_topic_stats(user_id, subject_id, topic_key, …, recent)`: одна строка на тему предмета. Обновляется в той же транзакции, что и ответ (`AttemptRepository.SubmitAnswer`). Внешнего ключа на вопросы нет, поэтому удаление персональных тестов статистику не трогает.
- Уровень темы считается в `models.TopicStat.Level()` по последним 10 ответам:

| Ответов в окне | Ошибок | Верно | Уровень |
|---|---|---|---|
| < 3 | — | — | ⚪ мало данных |
| ≥ 3 | < 2 | любое | 🟢 |
| ≥ 3 | ≥ 2 | ≥ 80% | 🟢 |
| ≥ 3 | ≥ 2 | 50–79% | 🟡 |
| ≥ 3 | ≥ 2 | < 50% | 🔴 |

  Пороги согласованы с объёмом данных: в тесте ~4 вопроса на тему, поэтому одного теста хватает, чтобы выявить систематическую ошибку (0–1 из 4 → 🔴, 2 из 4 → 🟡). Одна ошибка (3 из 4) — не слабость. Окно в 10 ответов позволяет теме выйти из списка после 1–2 уверенных прохождений.
- Не считается: верный ответ на вопрос, который *до ответа* уже был 🟢.
- Сортировка: 🔴, затем 🟡, внутри по доле верных; в тест идут 5 худших тем.
- `user_personal_done` и `tests.origin_test_id` хранят, какие персональные тесты пользователь уже закончил (по всей линии клонов). Такие тесты ему повторно не выдаются, вместо них генерируются новые вопросы.
- Бэкфилл `BackfillTopicStats` выполняется один раз при старте: восстанавливает статистику из истории `attempt_questions` по тем же правилам, что и для живых ответов.

Сценарии покрыты тестами `internal/services/weak_topics_integration_test.go` и `internal/models/topic_stats_test.go`.
