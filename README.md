# JUZ40 Tester

Telegram-бот для подготовки к ЕНТ/УБТ для школьников 9–11 классов (JUZ40). Стек: Go, Telegram Bot API (webhook), PostgreSQL (Neon) + pgx/v5, **Groq API (бесплатно: GPT-OSS 120B + Qwen 3.8 27B)** + DeepSeek API (платный резерв), Docker, Render.

## 💸 Groq: бесплатные модели вместо DeepSeek

С `GROQ_API_KEY` почти вся ИИ-работа уходит на бесплатный тариф Groq, DeepSeek вызывается только как резерв:

| Задача | Модель | Резерв |
|---|---|---|
| Перевод теста на казахский | `qwen/qwen3.8-27b` (instruct, без рассуждений — быстро) | `openai/gpt-oss-120b` → DeepSeek |
| Генерация chain-тестов | `openai/gpt-oss-120b` (reasoning medium → low) | Qwen → DeepSeek |
| Тест по слабым темам | `openai/gpt-oss-120b` (reasoning low) | Qwen → DeepSeek |

Лимиты Free-плана (на каждую модель): **30 RPM · 1 000 RPD · 8 000 TPM · 200 000 TPD**, причём 8 000 TPM — это ещё и максимальный размер одного запроса (prompt + max_tokens). Бот соблюдает их локально (скользящие окна + заголовки `x-ratelimit-*` + `retry-after`, запас 10%), режет перевод на куски, которые гарантированно влезают в один запрос, и при исчерпании квоты мгновенно переходит на следующую модель — ошибок 429/413 пользователь не увидит. Подробно: **[docs/GROQ_LIMITS.md](docs/GROQ_LIMITS.md)**.

Без `GROQ_API_KEY` бот работает ровно как раньше (только DeepSeek). Описание ниже про DeepSeek относится к резервному пути.

Тесты генерируются ИИ **одним дешёвым вызовом**: **deepseek-flash** (DeepSeek-V4.1-Flash) **в thinking-режиме** (`{"thinking":{"type":"enabled"}}` + официальный `reasoning_effort`) пишет весь тест из 20 вопросов, сам проверяя ключи ответов. Усилие адаптивное: chain-тесты (по одному на предмет, общие для всех учеников) — `reasoning_effort=high` («средний» уровень думания), персональные тесты по слабым темам и все ретраи — `low`. Итог ≈ **$0.002–0.006 за тест** (жёсткий потолок одного вызова ~$0.0096 по пиковому тарифу — `max_tokens=8000`, покрывает и скрытые thinking-токены). Старые имена моделей `deepseek-chat`/`deepseek-reasoner` **удалены из API 24.07.2026** и не используются; если thinking-параметры отвергаются (старый прокси) — клиент прозрачно откатывается на **deepseek-v4-pro** (non-thinking, дороже — только fallback). Каждый вызов логирует реальные токены и оценку стоимости (off-peak/peak + сумма за сессию) — чек всегда виден в логах сервера. При пустой цепочке предмета Тест 1 ставится в очередь немедленно при старте. Без `DEEPSEEK_API_KEY` генерация выключена — предмет останется без тестов.

## Возможности

- **Регистрация**: `/start` создаёт пользователя или обновляет его данные.
- **Главное меню** — обычные Reply-кнопки внизу чата: 📚 Предметы · 🎯 Слабые темы · 📊 Статистика · ⚙️ Настройки. Inline-кнопки используются внутри экранов предметов/тестов/результатов.
- **Список предметов** — InlineKeyboard по **1 кнопке в ряд** (на всю ширину, длинные названия читаемы); у каждого предмета **свой эмодзи** (📐 Математика, 📖 Грамотность чтения, 🧬 Биология и т.д.).
- **Стартовый предмет («Биология»)** — тестов-заглушек больше нет: всю цепочку строит ИИ (Тест 1, 2, … до 50), начиная с базового уровня школьной программы.
- **ИИ-генерация тестов (DeepSeek)** — один вызов **deepseek-flash** (thinking) на тест с адаптивным `reasoning_effort` и жёстким `max_tokens` (предел действует и на скрытые thinking-токены). Экономия достигается так:
  - промты компактные: прошлый тест передаётся строками «тема — короткая суть вопроса (≤80 символов) — уровни ученика», БЕЗ вариантов ответов; поле `why` из JSON-контракта убрано;
  - никакого отдельного шага шлифовки: модель один раз пишет тест и сама проверяет ключи;
  - персональный тест по слабым темам получает только короткие названия тем (пара слов каждая) — промт крошечный;
  - **шеринг по отпечатку тем**: два ученика с одинаковым набором слабых тем получают один и тот же тест — второму достаётся бесплатный клон без вызова ИИ вообще;
  - локальный валидатор JSON-контракта (ровно 20 вопросов, 4 варианта, `correct_index` 0–3, без дублей, без перекоса ключей; для weak-теста — строго запрошенные темы, все покрыты) — сломанный ответ никогда не попадает в БД.
- **Цепочка тестов с ПЛАВНОЙ прогрессией сложности**: модель видит прошлый тест с уровнями знаний ученика по каждому вопросу (0=не знает, 1=в процессе, 2=закреплено) и обязана сделать следующий тест лишь немного сложнее (диапазон difficulty: 1–2 → 2–3 → 3 → 3–4 → 4–5, верхняя планка только с 13-го теста), без повторов вопросов и с упором на слабые темы (отметки 0–1).
- **Правило разблокировки**: следующий тест открывается, когда предыдущий доведён до **15🟢 + 5🟡** (закреплено + в процессе). Закрытые тесты помечены 🔒, тап по замку показывает, чего не хватает. Проверка устойчива к «дырам» в нумерации цепочки: блокирующим считается первый непройденный тест, поэтому Тест 1 всегда доступен, даже если часть старых тестов удалена.
- **Генерация только тогда, когда это нужно**: закрытые (ещё не открытые) тесты предгенерируются только в off-peak часы (официальное расписание DeepSeek: пик — 01:00–04:00 и 06:00–10:00 UTC по будням, всё остальное включая выходные — полцены; при работе через прокси с другим расписанием окно переопределяется `GEN_OFFPEAK_START_HOUR`/`GEN_OFFPEAK_END_HOUR` в локальном времени сервера). Но тест, который пользователь уже МОЖЕТ открыть, а он ещё не сгенерирован, генерируется **СРОЧНО** (urgent-джобы игнорируют `not_before` и идут в воркере первыми) — пользователь никогда не ждёт off-peak окна. Тап по ⏳ отвечает «Минуточку, тест генерируется…».
- **🎯 Слабые темы (в главном меню)**: персональный тест из 20 вопросов по темам, где у ученика 🔴/🟡 (пять самых слабых). Тест **свой у каждого ученика** (`kind='personal'`, `owner_user_id`) и создаётся ТОЛЬКО по явному тапу (автогенерации при открытии предмета больше нет). Незаконченная попытка продолжается с того же вопроса; когда тест доведён до 15🟢 + 5🟡, появляется кнопка «🏁 Закончить тест» — тест удаляется вместе с вопросами, и при следующем заходе генерируется новый по актуальным пробелам.
- **Экран предмета** — сетка тестов **по 3 в ряд** (а не в столбик), до **50 тестов**, с пагинацией ⬅️ Назад / Вперёд ➡️ (по 12 на страницу). **Страница запоминается**: вышел на 5-й странице — вернёшься на 5-ю. Метки: ✅ пройден на 15🟢+5🟡, ⏸ есть незавершённая попытка, ⏳ тест генерируется, 🔒 закрыт.
- **Очередь генерации** в PostgreSQL (`generation_jobs`): идемпотентная (частичные уникальные индексы не дают задвоить задачи), с ретраями (до 3 попыток, backoff 10 мин) и статусами pending/running/done/failed. Зависшие «running»-джобы (погибший воркер, деплой, OOM) автоматически возвращаются в очередь через 10 минут. Фоновый воркер разбирает очередь каждые 20 секунд, `FOR UPDATE SKIP LOCKED` — безопасно при нескольких инстансах.
- **Новая попытка**: порядок 20 вопросов и порядок вариантов A/B/C/D каждого вопроса перемешиваются и **сохраняются в `attempt_questions`**. Проверка ответа идёт по сохранённому порядку, а не по исходной букве. При продолжении попытки ничего не перемешивается заново.
- **Ответ**: сообщение с вопросом **остаётся на месте** и переходит в финальное состояние: «🟢 Правильно» либо «🔴 Неправильно» + «🟢 Правильный ответ: …», выбранный вариант помечается 🟢/🔴, правильный всегда 🟢, плюс строка «Уровень вопроса: 🔴 0 / 🟡 1 / 🟢 2». **Клавиатура A/B/C/D у отвеченного вопроса удаляется** — нажать повторно нельзя. **Следующий вопрос отправляется отдельным НОВЫМ сообщением** сразу под отвеченным. Кнопки ответов — полноширинные, с текстом варианта («A) Ответ A»).
- **Система знаний** по паре `user_id + question_id`: 🔴(0) → 🟡(1) → 🟢(2):
  - правильно: 🔴→🟡, 🟡→🟢, 🟢→🟢
  - неправильно: 🔴→🔴, 🟡→🔴, 🟢→🟡
  - плюс счётчики правильных/неправильных ответов.
- **Результат** после 20-го вопроса: 🟢 Закреплено / 🟡 В процессе / 🔴 Требует повторения (состояние вопросов пользователя после прохождения) и «Результат: X/20». Кнопки: 🔄 Пройти тест ещё раз (новая попытка!), 📚 К предметам, ⬅️ Главное меню.
- **Прогресс**: сначала выбор предмета (InlineKeyboard по 1 в ряд, с эмодзи предмета), затем статистика только выбранного предмета — количество 🟢/🟡/🔴 и всего вопросов (нулевая статистика, если предмет не проходили).
- **DeepSeek API**: клиент `internal/deepseek` (OpenAI-compatible chat completions, JSON Output mode). Основная модель — env `DEEPSEEK_REASONER_MODEL` (по умолчанию `deepseek-flash`) в thinking-режиме с `reasoning_effort` high/low по типу задачи; `DEEPSEEK_MODEL` (по умолчанию `deepseek-v4-pro`, non-thinking) — только запасной вариант, если thinking-параметры отклонены прокси. Промты нацелены на подготовку к ЕНТ/УБТ (9–11 классы, школьная программа Казахстана). Без ключа генерация просто выключена.
- **🚪 Выйти**: сначала подтверждение «Выйти из теста?» (✅ Да, выйти / ↩️ Нет, продолжить), чтобы случайный тап не прерывал прохождение. При выходе попытка сохраняется; при повторном открытии теста она продолжается с текущего вопроса.

## Гарантии

- Ответ не засчитывается дважды при повторном callback (блокировка строки + guard `answered = FALSE` в одной транзакции).
- Проверяется, что попытка принадлежит пользователю.
- Каждый запуск теста — отдельный `test_attempt` (кнопка «🔄 Пройти тест ещё раз» создаёт новую попытку с новыми порядками вопросов и вариантов).
- Все изменения ответа выполняются атомарно в одной PostgreSQL-транзакции; переход статуса 🔴🟡🟢 считается от заблокированного (`FOR UPDATE`) предыдущего статуса.
- Секреты — только через переменные окружения.
- Миграции применяются автоматически при старте (embedded SQL).
- Генерация не может задвоиться: частичные уникальные индексы на `generation_jobs` + `ON CONFLICT DO NOTHING`; параллельная вставка одинакового weak-теста разрешается через уникальный индекс по отпечатку тем (проигравший гонку читает готовый тест).
- Сломанный ответ модели никогда не попадает в БД: строгая валидация JSON-контракта до записи; сбой reasoner откатывается на валидный черновик.
- Задачи генерации не блокируют UI: все вызовы DeepSeek идут только в фоновом воркере.

## Структура

```
cmd/bot/          точка входа (HTTP-сервер, webhook, фоновый воркер генерации)
internal/
  bot/            минимальный клиент Telegram Bot API (inline + reply клавиатуры)
  config/         загрузка конфигурации из env (модели, off-peak окно)
  database/       подключение pgxpool + миграции
  deepseek/       клиент DeepSeek (chat + reasoner, JSON mode) — платный резерв
  groq/           клиент Groq + локальный rate limiter (RPM/RPD/TPM/TPD)
  handlers/       обработчики сообщений и callback-ов (сетка тестов, пагинация)
  models/         доменные модели и правила системы знаний
  repositories/   SQL-доступ к данным (включая очередь генерации и state)
  services/       бизнес-логика (попытки, результаты, цепочка unlock, генератор)
migrations/       SQL-миграции (embed)
questions/        определение стартового предмета (без тестов-заглушек)
Dockerfile        multi-stage сборка для Render
```

## База данных

Таблицы: `users`, `subjects`, `questions`, `tests` (+`kind`, `topics`, `topics_fingerprint`), `test_questions`, `test_attempts`, `attempt_questions`, `user_question_progress`, `user_subject_state` (страница сетки тестов, водяные знаки цепочки), `generation_jobs` (очередь ИИ-генерации), `schema_migrations`.

Seed при старте создаёт стартовый предмет (идемпотентно) и, если цепочка пуста, немедленно ставит Тест 1 в очередь генерации. Дальше цепочку продолжает генератор. Миграция `000002` очищает старые сид-предметы, `000003` добавляет инфраструктуру ИИ-генерации, `000004` удаляет тесты-заглушки «Биологии» вместе с их вопросами и прогрессом по ним.

## HTTP

- `GET /health` — проверка живости (включая ping БД)
- `GET /ping` — лёгкий keep-alive endpoint (только в коде, в интерфейсе бота не отображается). Встроенный self-ping каждые 5 минут обращается к `WEBHOOK_URL/ping`, чтобы сервис не засыпал на бесплатном тарифе Render и фоновый воркер генерации продолжал работать.
- `POST /telegram/webhook` — приём обновлений Telegram

## Деплой на Render (Docker)

1. Создать Neon PostgreSQL и скопировать `DATABASE_URL`.
2. Render → New → Web Service → Docker (репозиторий подключается как есть).
3. Задать переменные окружения: `BOT_TOKEN`, `DATABASE_URL`, `WEBHOOK_URL` (URL, который выдаст Render, вида `https://<name>.onrender.com`), плюс `GROQ_API_KEY` (бесплатная ИИ-генерация и перевод) и `DEEPSEEK_API_KEY` (платный резерв).
4. После деплоя бот сам применит миграции (включая удаление старых тестов-заглушек), создаст предмет, поставит Тест 1 в очередь генерации, выставит webhook и запустит фоновый воркер генерации.
